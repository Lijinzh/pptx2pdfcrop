安装与快速开始

平台要求：目前仅支持 Windows 10/11，必须安装桌面版 Microsoft PowerPoint。不支持 macOS、Linux、PowerPoint 网页版或 WPS。

最快方式：复制给 Codex

把下面整句话复制给 Codex，它会完成安装、环境检查，并给出第一条可运行命令。

请在这台 Windows 电脑上从 https://github.com/Lijinzh/pptx2pdfcrop 安装最新版 pptx2pdfcrop，运行 pptx2pdfcrop doctor 检查桌面版 Microsoft PowerPoint 自动化环境；验证成功后告诉我安装位置，并给我一条导出第 9 页为裁切 PDF 的示例命令。

手动安装

uv tool install git+https://github.com/Lijinzh/pptx2pdfcrop.git
pptx2pdfcrop doctor

doctor 成功时会确认 Windows、PowerPoint COM 和两条导出管线均可用。

命令与参数

导出一页

pptx2pdfcrop export drawing.pptx --slides 9

导出多页并指定输出

pptx2pdfcrop export drawing.pptx --slides 3,5,9-12 --output figures.pdf

常用选项

选项作用默认值
--slides1-based 页码、范围、逗号列表或 all1
--modevector 或 compatiblevector
--white-threshold判定近白像素的阈值，越低裁切越激进255
--padding内容四周保留的安全边距，单位 pt0.5
--crop-dpivector 模式检测内容边界时的渲染分辨率576
--dpicompatible 模式的 PowerPoint TIFF 分辨率600
--compressionjpeg 或 losslessjpeg
--jpeg-qualitycompatible JPEG 质量，使用 4:4:4 色度采样92
--force允许覆盖已有输出文件关闭
--json输出机器可读结果关闭

两种导出模式

vector：默认且推荐

PowerPoint 先导出原生 PDF。工具以高分辨率渲染副本检测内容边界，但最终只平移原始 PDF 内容流并重设 MediaBox、CropBox 等页面框，因此不会把文字和路径栅格化。

compatible：复杂效果兜底

PowerPoint 按指定 DPI 输出 TIFF，从无损 TIFF 上检测并裁切内容，再以 JPEG 4:4:4 或 LZW TIFF 写入图片 PDF。它牺牲矢量可编辑性，换取透明、渐变和软遮罩在不同阅读器中的一致性。

pptx2pdfcrop export drawing.pptx --slides 9 --mode compatible
pptx2pdfcrop export drawing.pptx --slides 9 --mode compatible --compression lossless

整个项目的实现逻辑

CLI 把用户输入转换成不可变的 ExportOptions，统一管线负责验证、选择模式、管理临时目录和原子写入。PowerPoint 始终运行在独立隐藏实例中，并在成功或异常时关闭。

1. CLI 与页码解析cli.py 解析参数；pages.py 把 1,3-5 规范化成有序页码。
2. 统一管线pipeline.py 验证平台、输入、输出与质量参数，并在目标目录创建临时工作区。
3. PowerPoint 后端powerpoint.py 通过 pywin32 COM 只读打开演示文稿，复制所选页面并执行 PDF 或 TIFF 导出。
4. 内容边界检测geometry.py 从 RGB 三通道中找到非白像素，扩展安全边距，并拒绝完全空白的页面。
5A. Vector 裁切vector_pdf.py 用 PDFium 渲染检测，再通过 pypdf 平移原始内容、收紧所有页面框。
5B. Compatible 编码raster_pdf.py 裁切 TIFF，保存 JPEG 4:4:4 或 LZW TIFF，再无二次重编码地嵌入 PDF。
6. 安全提交结果确认候选 PDF 存在且非空后，使用 os.replace 原子替换目标；临时目录自动清理。

为什么要复制演示文稿再删页？

PowerPoint 的打印页码会受到自定义起始页码影响。项目先保存临时副本，再从后向前删除未选择页面，避免页码映射错误，同时不修改用户源文件。

为什么 vector 仍然需要渲染？

渲染只用于确定内容边界。最终输出使用原 PDF 的内容流，因此既能准确裁边，又能保留矢量质量。

项目结构与模块职责

模块职责
cli.py命令参数、doctor、终端与 JSON 输出
models.py导出选项和结果数据模型
pages.py页码表达式解析、范围校验与文件名标签
powerpoint.pyCOM 生命周期、演示文稿读取、PDF/TIFF 导出
geometry.py非白像素检测、边界扩展与栅格裁切
vector_pdf.py矢量 PDF 内容检测、平移与页面框重设
raster_pdf.pycompatible 模式裁切、编码与 PDF 组装
pipeline.py验证、模式编排、临时目录与原子写入

如何贡献自己的代码

建立开发环境

git clone https://github.com/Lijinzh/pptx2pdfcrop.git
cd pptx2pdfcrop
uv sync --extra dev
uv run ruff check .
uv run pytest
uv build
uv run pptx2pdfcrop doctor

普通单元测试不启动 PowerPoint；端到端导出验证必须在安装了桌面版 PowerPoint 的 Windows 机器上执行。

提交前必须注意

  • 不要提交测试用 PPT、论文原图、临时 TIFF 或生成 PDF。
  • 新增裁切逻辑时，覆盖纯白背景、近白色渐变和零安全边距。
  • 修改默认 DPI、JPEG 质量或色度采样时，给出文件体积与放大画质对比。
  • PowerPoint COM 必须使用独立实例、只读打开源文件，并保证异常时关闭。
  • 用户可见文档优先简体中文，并同步必要英文内容。
  • 官网改动需要检查 1440px 桌面和 390px 移动视口。

Pull Request 应包含

  1. 修改解决了什么问题；
  2. 使用了什么 PPT 和页码验证；
  3. 输出 PDF 的 DPI、压缩参数和大小变化；
  4. 是否影响默认 vector 或可选 compatible 模式。

限制与排错

  • doctor 失败：确认正在 Windows 上运行，并安装桌面版 Microsoft PowerPoint。
  • 导出的不是最新编辑：工具读取磁盘中已保存版本，请先在 PowerPoint 中保存。
  • 复杂透明显示不同：先尝试修正源素材；仍不一致时使用 --mode compatible。
  • 边缘被裁掉：提高 --padding，或将 --white-threshold 保持为 255。
  • 输出已存在：更换 --output，或明确使用 --force。
